Project: Issue Tracker

Problem
Teams that ship a product need one place to record what’s broken, who is looking at it, and what has been fixed. Without it, problems get lost in chats and emails. The Issue Tracker gives companies a central list they can add to, update, and clean up.
My role
I built the backend as part of my coursework: starting the server, writing the routes, adding middleware, validating requests, and creating, updating, and deleting records in the database. I also deployed it so it runs on the web.
What I built
  • A REST API with endpoints to create, read, update, and delete issues
  • Request validation with Zod so bad data is rejected early
  • Comments and test cases stored inside each issue
  • Filtering, sorting, search, and pagination for the issue list
  • Hosting on Google Cloud Run

Tech stack: TypeScript, Node, Express, MongoDB Atlas, Zod.

What I’d improve
I’d set up automatic deployment (CI/CD) so a push to GitHub ships a new version without manual steps. I’d also add a simple front-end so non-developers can use it, plus user accounts and more automated tests.
